# Security policy

## Reporting a vulnerability

Do not open a public issue for a suspected credential leak, authentication bypass, unsafe file write, or privacy vulnerability.

Until GitHub private vulnerability reporting is enabled for the public repository, report privately to the repository owner through GitHub. Include reproduction steps without real credentials, tokens, private endpoints, or full local configuration files.

## Response principle

Credentials that may have been exposed must be revoked or rotated first. Removing a file from a later commit does not make a previously public secret safe.

## Supported versions

No public release is supported yet.
